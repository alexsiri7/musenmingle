# The map (`/map`): self-hosted tiles and libraries

`/map` ("Near me, right now", `src/web/map.rs` + `src/map.mjs`) draws a
map of London without any third-party server: the tiles, the map library,
the styles and the label fonts are all served by our own API. Public
OpenStreetMap tile servers and map CDNs are not meant for app traffic, and
our `/about` promises no third-party assets.

## Tiles: `static/tiles/london.pmtiles`

One [PMTiles](https://github.com/protomaps/PMTiles) file: a Greater London
extract of the [Protomaps](https://protomaps.com) basemap (OpenStreetMap
data, ODbL; attribution "© OpenStreetMap contributors · Protomaps" is shown
on the map and links to <https://www.openstreetmap.org/copyright>).

It is committed to the repository (under GitHub's 100 MB file limit, so no
LFS) and copied into the Docker image at
`/usr/share/musenmingle/london.pmtiles` (`TILES_PATH`). The API serves it at
`GET /tiles/london.pmtiles` with HTTP range requests (tower-http
`ServeFile`: `Accept-Ranges`, `206` + `Content-Range`, `416`); the page
links `?v=<hash of the first 16 KiB>` and that URL is cached for a year.
If the file is missing the API still starts and `/map` shows only its
list.

### Refreshing the extract (quarterly is plenty)

Protomaps keeps daily builds for about a week, so pick a current one from
<https://maps.protomaps.com/builds/> and extract with the
[`pmtiles` CLI](https://github.com/protomaps/go-pmtiles/releases) (v1.31.2
used here). It reads only the needed byte ranges (~60 MB), not the planet:

```bash
pmtiles extract https://build.protomaps.com/<YYYYMMDD>.pmtiles static/tiles/london.pmtiles \
  --bbox=-0.5103,51.2868,0.3340,51.6919 --maxzoom=14
pmtiles show static/tiles/london.pmtiles   # check bounds, zoom 0-14, tile type mvt
sha256sum static/tiles/london.pmtiles
```

Update the table above, and check the page. Every refresh adds the file's
size (~56 MB) to the repository history; if that becomes a problem, move it
to a Railway volume (and set `TILES_PATH`) instead. A basemap major version
change may need regenerated styles (below).

MapLibre's own stylesheet is not loaded: the few layout rules it needs are
in `src/web.css`, and its controls are replaced by our own (square zoom
buttons, the attribution chip). MapLibre decodes tiles in a same-origin
module worker (`maplibre-gl-worker.mjs`, next to the main module), so the
page's CSP only adds `worker-src 'self'` (no `blob:`); the styles have no
sprite and no remote URLs (tests check this). Glyph ranges and font stacks
we don't ship (e.g. Devanagari labels) are answered with an empty glyph
set, so those labels are skipped.

To upgrade a library: `npm pack <name>@<version>`, copy the same files into
a new versioned directory, update `MAPLIBRE_DIR`/`PMTILES_DIR` and
`MAP_ASSETS` in `src/web/map.rs`, and this table.

## Location privacy

"Use my exact coordinates" calls the browser's Geolocation API only when
tapped (the `/map` and `/` responses set `Permissions-Policy:
geolocation=(self)`; every other response keeps `geolocation=()`). The
position never leaves the browser: `map.mjs` fetches the London-wide
`GET /v1/events?at=now` (or `at=today`) listing, which has no location in
it, and computes distances and walking times itself. Without JavaScript,
or if location is refused, the page lists events near an area preset.

The home page's "Near me" filter (issue #173) is different: "Use my
location" rounds the position to 3 decimals (about 100 m) in `web.js` and
submits it as `here=<lat>,<lng>&walk=<10|20|30>`, which the server rounds
again and turns into `near=` + `within_walk_min=` (the same 5 km/h × 1.3
detour estimate as the map's "≈ N min walk"). The server keeps no request
logs, so the position is not stored anywhere.

## Venue coordinates: `events.venues`

Listings without coordinates can't be mapped. `events.venues` (migration
`20260927990001_venues.sql`) holds hand-seeded points for venues that
sources list without them; `repo::upsert_event` fills a listing's missing
lat/lng from it when the normalised venue name matches (a source's own
coordinates always win). Add venues with a new migration; there is no
automatic geocoding.
